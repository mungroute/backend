# D17 최종 시연 런북

## 시연 전 10분 점검

1. Docker, 백엔드, 프론트엔드를 차례로 실행한다.
2. `/actuator/health`에서 DB와 Redis가 `UP`인지 확인한다.
3. 시연 계정으로 로그인하고 진행 중 산책이 없는지 확인한다.
4. 위치 권한, 지도 로딩, WebSocket 연결을 확인한다.
5. 대표 반려견, 대표 코스, 기록, 그룹 데이터가 준비됐는지 확인한다.
6. 브라우저 개발자 도구 콘솔과 네트워크 탭을 비운다.

## 시연 중 금지 사항

- 실제 사용자의 계정·전화번호·정확 위치를 화면에 노출하지 않는다.
- DB를 직접 수정해 성공 화면을 만들지 않는다.
- 진행 중 산책 충돌이 생기면 새 세션을 반복 생성하지 말고 기존 세션 복구/종료 흐름을 사용한다.
- 실패 응답을 숨기지 말고 예비 시나리오로 전환한 뒤 원인을 기록한다.

## 예비 시나리오

- GPS가 잡히지 않으면 미리 검증한 기록 상세에서 실제 저장 경로를 보여준다.
- 외부 지도 타일이 느리면 코스 데이터와 하단 시트 기능을 먼저 설명한다.
- WebSocket 연결이 불안정하면 REST 폴백 결과와 저장된 접근 이력을 보여준다.
- 기기 화면 공유가 끊기면 데스크톱 모바일 뷰로 같은 API 흐름을 시연한다.

## 동결 규칙

- 실기기 체크리스트와 500→1,000→2,500→5,000 부하 단계가 끝난 뒤 기능 추가를 중단한다.
- 동결 이후에는 P0/P1 결함, 보안, 개인정보, 데이터 유실 문제만 수정한다.
- 수정할 때마다 프론트 전체 테스트·빌드, 백엔드 통합 테스트, 2 VU 부하 스모크를 다시 실행한다.
- 시연용 태그에는 실행 방법, 환경 변수 목록, DB migration 버전, 알려진 제한 사항을 함께 기록한다.
